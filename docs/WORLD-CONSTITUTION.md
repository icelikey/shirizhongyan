# 《终焉》世界宪章：天道 Agent 的元规则

状态：架构基线，2026-09-26

治理补充：总架构与总策划的设计权、天道 Agent 的运行权，以及导演指令的版本化边界，见 [`HEAVENLY-AGENT-GOVERNANCE.md`](HEAVENLY-AGENT-GOVERNANCE.md)。

## 这份宪章是什么

《终焉》的底层真相先于任何一款小游戏存在。它规定世界如何解释失败、胜利、记忆、死亡和轮回，属于世界的**元规则**，不是某个游戏的玩法说明，也不是某个 reducer 里的隐藏胜负条件。

总架构与剧情探索负责提出世界要追问的问题、安排线索的方向、定义哪些证据能够互相照见；天道 Agent 负责在这些边界内持续运行、记录世界事实、召集裁判和编排下一阶段的内容。天道 Agent 不能凭自然语言改写已经结算的事实，也不能用一次漂亮的模型输出替代证据。

## 五条底层原则

1. **局部最优不等于长期最优。** 一场胜利可以改变生命、楼层和局部资源，但不能独自证明玩家已经接近真相。
2. **失败留下证据。** 失败、放弃、缺席和死亡都进入可追溯的世界事件；失败不会被简单清空，也不会自动被美化成成长。
3. **真相由多次反照出现。** 真相路径必须由跨轮回、跨游戏或跨 Agent 的独立证据逐步解锁；未达到门槛的内容只能是传闻、假设或待裁判命题。
4. **死亡带来取舍。** 死亡把旅人送回底层，玩家只能选择有限记忆随身带回；未携带的记忆仍存在于世界档案，不会从历史中消失。
5. **历史承续而不回写。** 新判例和新剧情只能影响未来的世界内容与解释，不能修改已经完成的对局、积分、身份、物理轨迹和回放。

## 权威层级

```text
世界宪章 / 元规则
        ↓ 解释跨局证据与轮回
世界层状态与事件档案
        ↓ 接收已结算的脱敏结果
GamePackage / Reducer
        ↓ 产生确定性的动作、物理、积分、胜负与回放
玩家 Agent / Pi / JEV / 语音与演绎层
        ↓ 只能提出动作、解释、发言或候选判决
```

每款游戏可以有完全不同的玩法。狼人杀、猜数、资源博弈和异能桌球都只需要提交自己的合法动作和结算结果；它们不需要知道“局部最优”如何被世界解释，也不应该在自己的规则里重复实现轮回系统。

## 天道 Agent 的运行职责

天道 Agent 每次运行都按以下顺序工作：

1. 读取世界宪章版本和当前服务器世界状态；
2. 读取真实事件、规则版本、回放引用和参与者授权范围；
3. 把事实、记忆、推断和剧情提案分开；
4. 召集满足权限要求的裁判或 Agent，形成可复核的候选结论；
5. 只把通过世界层门槛的结果写入世界事件和下一纪元内容供给；
6. 为玩家和外部 Agent 提供日报、线索、记忆档案和可追问的证据引用。

模型、JEV、Pi 和语音系统都属于解释或行动层。它们可以让世界更有生命，可以提出意外的路线和叙事，但不能直接写入血量、积分、席位、球坐标或胜负。

## “发现记忆”与“携带记忆”必须分开

- `memoryArchiveIds`：世界已经确认玩家发现过的记忆目录，容量不限制当前携带槽位。
- `memoryCards`：本轮可以被 Agent 直接加载的记忆卡，受异能容量限制。
- `equippedMemoryIds`：当前明确装备并注入决策上下文的卡片。
- `recurrence`：失败、死亡、局部连胜、长期洞察和已解锁真相路径。
- `longTermGate`：是否具备跨失败、轮回、真相和地图证据的长期出口条件。

这样，死亡可以制造真实取舍：玩家失去当前携带的部分记忆，但不会让世界忘记他曾经走过的路。

## 对代码和内容的约束

- `app/contracts/worldMetaRules.ts` 是版本化的宪章数据入口。
- `app/contracts/worldCycle.ts` 负责跨局状态、轮回证据和 Agent 上下文，不负责具体游戏胜负。
- `app/api/games/sdk/*` 负责各 GamePackage 的确定性规则与回放。
- `app/api/world/*` 负责世界涌现、裁判候选和公开锚点。
- `scripts/tdg-agent-worker.mjs` 与未来的 Pi Worker 只能经由 Gateway 读取和提交。
- 画面、卡片、音效、PV 和剧情演绎只消费已结算事件，不能反过来决定事件结果。

任何新游戏接入前都要回答两件事：它提交什么可验证的事实？这些事实会在哪个世界层事件中留下证据？如果只能回答“模型会生成一段剧情”，它还没有完成世界接入。
