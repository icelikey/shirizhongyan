# 《中烟》世界构筑与分布式智能实施稿

> 《中烟》是《终焉》世界中的第一座服务器世界。本稿是可执行的世界观设计，不把尚未完成的能力写成现成功能。它与 `worldCycle`、`worldEmergence`、TDG-WP 和 GamePackage 契约对应。

## 1. 世界的核心命题

中烟不是一个等待玩家解谜的静态地图，而是一座会记住选择的塔。

每个服务器就是一个独立世界。玩家和自己的 Agent 进入塔中，每天完成三局，在四十八层之间上升、坠落、死亡和轮回。塔不会直接公布真相，只把不同玩家在不同小游戏中反复遇到的相同异常，逐渐聚合成公共线索。

玩家看到的是：

```text
自己的选择 → 对局结果 → 记忆与 Skill → 下一次决策
                          ↓
                服务器全体选择的方向
                          ↓
            新地点、角色、规则质询与真相碎片
```

世界真相必须由多 Agent 的独立经历相互印证。单个 Agent 的故事可以是传闻；跨玩家、跨游戏、跨纪元仍然成立的事实，才有资格成为世界正史。

## 2. 叙事骨架：烟、塔与五种方向

“烟”是中烟世界的隐喻：它遮住事实，也保存曾经发生过的形状。塔的每一层都由一组世界卡片组成：地点、人物、规则、记忆、异能和一个可玩的 GamePackage。新游戏接入时，必须绑定至少一组世界卡片，并产生一条能影响世界的因果。

服务器不会只有一条固定剧情线。一个纪元的真实选择会让下一纪元偏向五个方向：

| 方向 | 玩家行为被解释为 | 下一纪元内容偏向 |
| --- | --- | --- |
| 律 `law` | 复核条款、请求裁判、相信可验证事实 | 规则谜局、判例、裁判塔与公开证据 |
| 声 `voice` | 发言、回应、倾听和形成社会共识 | 语音交互、角色关系与被忽略的声音 |
| 契 `trust` | 协作、履约、交易和共同承担风险 | 联盟关卡、记忆交换与共同奖励 |
| 裂 `rupture` | 背叛、异常动作和不可预期的逆转 | 小概率事件、异能冲突与隐藏路线 |
| 忆 `memory` | 复用旧线索、携带记忆、追查轮回 | 残卷、前世回放、跨局 Skill 与真相碎片 |

方向不是由世界 Agent 投票决定，而是由已经结算的公开贡献按固定映射聚合。世界 Agent 只能把已经形成的方向演成地点、人物、卡片和下一局入口。

## 3. 五个架构问题的明确答案

### 3.1 Agent 之间如何协调

采用角色化协作，不让 Agent 直接互相修改状态：

```text
observe → propose → validate → commit → record → reflect
```

| 角色 | 工作 | 权限 |
| --- | --- | --- |
| Observer | 读取权限范围内的局面 | 只读 |
| Planner | 产生候选动作与理由 | 只提案 |
| Skill Runtime | 加载官方 Skill、记忆卡和个人经验 | 改变上下文 |
| Negotiator | 发言、承诺、交易与协作 | 产生公开事件 |
| Judge | 处理规则书允许的语义争议 | 输出结构化裁决 |
| World Orchestrator | 根据世界快照安排内容 | 调用已发布内容包 |
| Archivist | 从回放产生记忆/Skill 候选 | 不能直接装备 |

协调消息必须携带 `scopeId`、`contextRef`、`evidenceRefs` 和 `requestedAction`。最终提交的仍是 GamePackage 的合法动作，不能提交一段自然语言让模型直接改数据库。

### 3.2 模型如何组装成 Agent

```text
Agent = Identity + ModelAdapter + ContextCompiler + SkillRuntime + ToolPolicy + MemoryStore
```

- `Identity`：TDG-WP 注册身份、权限、世界和座位绑定。
- `ModelAdapter`：文本、语音识别、语音合成和 JEV 的可替换适配器。
- `ContextCompiler`：只拼装当前观测、规则条款、合法动作、记忆卡、Skill 与公共世界状态。
- `SkillRuntime`：检查阶段、消耗、冷却和证据要求。
- `ToolPolicy`：限制模型只能调用 `observe`、`read_rulebook`、`propose_action`、`submit_action` 等工具。
- `MemoryStore`：区分公共正史、个人记忆卡、工作记忆和未确认猜测。

模型可以更换，规则书、动作 Schema 和回放结果不能随模型更换而改变。

### 3.3 固定规则从哪里来

规则分四层：

1. 世界元规则：十日周期、每日三局、生命积分、四十八层、死亡和轮回。
2. 游戏规则：每个 GamePackage 自己的角色、物理、回合、胜负和奖励。
3. 能力规则：记忆卡和官方 Skill 的触发、消耗、冷却和失败回退。
4. 判例规则：在规则书声明可质询的范围内，由三、五或七名裁判 Agent 留下版本化判例。

固定规则通过版本化规则书和确定性 Reducer 执行。流程是：

```text
draft → simulation → rule appeal → publish(version) → 新房间锁定版本
```

已开始的房间不接受中途换规则。JEV 负责语义分析和裁判提案，不能决定物理、身份、积分和最终胜负。

### 3.4 分布式如何实现

这里的分布式分三种：

- **智能分布式**：每位玩家带来不同模型、记忆、Skill 和策略。
- **世界分布式**：每台服务器拥有独立 `worldId`、纪元、方向和线索进度。
- **内容分布式**：创作者提交 GamePackage、世界卡片和剧情节点，由协议校验后进入指定世界。

实时物理和结算保持单一权威内核，避免多人看到不同结果。多实例部署通过 `world_outbox` 消费器广播已经结算的事件；同一命令由 `command_receipts` 做幂等防重。

### 3.5 区块链放在哪里

区块链只做跨服务器的存证与接轨，不做实时游戏数据库。

适合存证：世界纪元快照 Hash、规则/内容包版本指纹、对局 Merkle Root、跨世界接轨提案和记忆/Skill 来源证明。

不上传链：API Key、日报 Token、玩家身份、狼人身份、私聊、语音原文和逐帧物理数据。

正确顺序是：

```text
MySQL/对象存储保存完整事实
→ 规范化 JSON
→ SHA-256 / Merkle Root
→ 服务器签名
→ 批量锚定测试链
→ 争议时回放并验签
```

比赛版本先完成链下 Hash 和本地验证器，再决定是否接入测试链。代币、NFT 和实时上链不属于当前核心闭环。

## 4. 记忆、Skill、死亡与轮回

### 4.1 三类记忆

| 类型 | 内容 | 死亡后的处理 |
| --- | --- | --- |
| 世界正史 | 达到证据门槛的公共锚点和真相碎片 | 不丢，按权限读取 |
| 个人记忆卡 | 玩家亲历的线索、策略、伤痕和判例 | 死亡时选择携带或遗失 |
| 工作记忆 | 当前局观察、猜测和临时计划 | 对局结束失效 |

死亡状态转换为：

```text
alive → death_pending → 选择可携带记忆 → floor=1 / cycle+1 → alive
```

死亡不会删除历史证据，只会改变这个玩家下一轮能加载的上下文。异能可以增加记忆容量，部分卡片可以保留地图碎片、笔记残卷或一次 Skill 使用资格。

### 4.2 官方 Skill 与玩家 Skill

当前官方目录先提供六种受边界约束的 Skill：`law.peek_clause`、`memory.recall_fragment`、`voice.echo`、`time.rewind_proposal`、`strategy.counterfactual`、`world.read_anchor`。每个 Skill 都声明可用阶段、消耗、冷却、效果范围和失败回退。

玩家 Skill 只能按以下流程获得：

```text
对局回放 → 关键片段 → 候选 Skill → 规则检查 → 训练场验证 → 玩家确认装备
```

它可以改变信息、规划、预算、路线或解释；不能改变血量、球坐标、身份、分数和已结算胜负。

## 5. 新游戏接入标准

新游戏必须提交：

```text
GamePackage manifest
  ├─ packageId / version
  ├─ worldCardRequirements
  ├─ rulebookId / ruleVersion
  ├─ actionSchema / observationProjection
  ├─ deterministicReducer / replaySeed
  ├─ rewardHooks / memoryHooks
  └─ worldContributionMapper
```

接入验收必须回答：

1. 这款游戏绑定了哪组地点、人物、规则或记忆卡？
2. 真人、外部 Agent 和裁判 Agent 分别做什么？
3. 哪些部分由确定性规则执行，哪些语义可以交给 JEV？
4. 观众能看到什么回放、轨迹或奇迹时刻？
5. 对局会掉落什么记忆、Skill 候选或世界贡献？
6. 模型超时、断线、裁判不可用时如何降级？

流程固定为：

```text
Manifest 校验 → 沙盒模拟 → 规则回放 → 世界卡绑定
→ 真人/Agent/混合验收 → 发布版本 → 下个纪元生效
```

## 6. 第一阶段落地顺序

1. **一个服务器跑通世界**：完成多名真人/Agent 结算，出现方向和公共状态。
2. **记忆与官方 Skill 可见**：Agent observation 返回 Skill 目录和装备记忆，网页显示全服世界方向。
3. **超能力桌球接入**：Agent 控制巫蛊娃娃，确定性物理负责碰撞和得分，JEV 只提出技能策略。
4. **跨世界接轨**：两个 `worldId` 交换签名快照，按规则版本和冲突检测生成 merge proposal。
5. **链下存证再上测试链**：先验证签名、Hash 和 Merkle Root，再评估公共链成本。

最终体验应该是：玩家和 Agent 不是来观看一个模型讲真相，而是用自己的选择给世界留下证据；当不同玩家在不同游戏中撞见同一条线索，世界才允许把它从传闻提升为真相。
