# 终焉｜山海经意象适配与掉落卡片契约

> 状态：主控工作台规范（候选内容接入规则）
>
> 目的：把山海经的异兽、山川、天象和志怪意象转成《终焉》自己的地点、人物、线索、卡片和事件，同时保持规则、事件流和最终真相的边界。

## 1. 适配原则

山海经在《终焉》中是视觉和行为的意象层，不是现成的神话数据库。它可以提供一种让玩家迅速理解“观测、辨伪、迁徙、资源、威慑、时间和记忆”的形象入口，但不会自动带来古籍中的身份、关系、神力或结局。

每个意象进入游戏前，必须被改写成一张原创设计卡，至少写清：

- 新世界中的名称、地点和首次出现周期；
- 它代表的行为倾向或信息问题；
- 可触发的游戏事件和玩家可见范围；
- 能力效果、冷却、代价和可反制方式；
- 对应的记忆碎片、地图碎片、笔记残卷或 Skill；
- 是否只是传闻，何时可以由独立事件升级为公共事实。

禁止用“古籍记载”替代规则条款、事件证据或裁判依据。视觉生成结果也不能反过来改写已经结算的事实。

## 2. 意象到玩法的五段映射

```text
山海意象
  → 原创行为锚点
  → 游戏中的可验证事件
  → 掉落卡片与使用代价
  → 跨游戏线索或服务器方向
```

| 意象方向 | 终焉中的原创问题 | 适合承载的玩法 | 首选掉落 |
|---|---|---|---|
| 异兽的辨识与伪装 | 看见的形状是否等于真实身份 | 狼人杀、证言推理、少数派票决 | 伪装残影、证词裂片、反制 Skill |
| 山川的阻隔与迁徙 | 路线选择会留下什么不可逆代价 | 超能力赛马、碎境爬塔、跨服务器接轨 | 地图碎片、路线记忆、坐骑异能 |
| 天象的周期与遮蔽 | 观测窗口是否决定事实的形状 | 猜平均数、虫心算谱、轮回 | 时间残响、观测权限、预测 Skill |
| 藏宝与守门 | 资源交换能否换来更深的信息 | 海盗分金、商店、交易 | 契约残卷、资源记忆、交换 Skill |
| 志怪与传闻 | 未证实故事如何变成公共事实 | 所有游戏的彩蛋与战报 | 传闻卡、证据索引、门禁线索 |

## 3. 每款游戏的世界接入卡

编剧稿只能进入 `work/worldbuilding/drafts/`。主控审查通过后，才可以复制为游戏接入卡并绑定 `GamePackage`。每款游戏至少填写：

```yaml
gameId: endgame.game.example
title: 游戏名
worldLocation: 地点 ID
cycle: 1
spireRange: [1, 3]
motif:
  sourceClass: beast|mountain|celestial|strange-tale
  originalAnchor: 本项目原创行为锚点
fixedBeats: []
generatedSlots: []
publicFacts: []
hiddenFacts: []
judgeRole: 裁判 ID 或裁判职责
shadowRoles: []
lineage: [world-card-id]
fragmentPool: [fragment-id]
skillPool: [skill-id]
worldContribution:
  metric: 服务器方向指标
  quorum: 需要的独立席位数
  capPerPlayer: 单玩家单周期贡献上限
fallback: 规则照常结算，叙事降级为事件摘要
```

固定剧情只规定必须建立的事实、门槛和回收；生成剧情只能填入开放槽位。一个模型不能凭旁白宣称“异兽已经出现”，必须引用房间事件、掉落事件或已发布内容卡。

## 4. 掉落卡片的数据契约

每局掉落由服务端用房间种子、规则版本和事件摘要确定性生成。展示可以带随机演出，但同一回放必须得到同一张卡。模型只能提出候选描述，不能决定卡片效果、稀有度或奖励数量。

```json
{
  "dropId": "drop-c01-game-001",
  "cardId": "memory-windless-banner",
  "type": "memory_fragment",
  "title": "无风之旗",
  "rarity": "uncommon",
  "sourceGame": "endgame.game.example",
  "sourceEventRefs": ["match-event:123", "settlement:123"],
  "canonStatus": "draft",
  "summary": "记录某个观测窗口中，旗面方向与现场风向不一致。",
  "effect": {
    "scope": "information",
    "gameBindings": ["endgame.game.example"],
    "grants": ["unlock:scene-archive-03"],
    "doesNotModify": ["victory", "score", "physics", "identity"]
  },
  "trigger": { "kind": "after_settlement", "conditions": ["independent_observers>=2"] },
  "cost": { "capacity": 1, "cooldown": 0, "risk": "may_expose_false_memory" },
  "portable": "cross_game_readonly",
  "evidenceRefs": [],
  "version": 1
}
```

### 4.1 五类卡片

| 类型 | 用途 | 可影响 | 不能影响 |
|---|---|---|---|
| `memory_fragment` 记忆碎片 | 记录经历、结构、人格或现实残留 | 观察、路线、剧情入口 | 已结算胜负和历史 |
| `map_fragment` 地图碎片 | 拼合地点、层级和跨游戏通道 | 可进入区域、门禁提示 | 直接跳过门槛 |
| `note_scroll` 笔记残卷 | 保存玩家推断、证词或战报索引 | 复盘、线索关联、交易 | 把推断变成事实 |
| `skill` Skill 卡 | 让 Agent 在合法窗口提出更好动作 | 信息投影、时机、预算、资源路径 | 直接改写规则和物理 |
| `ability` 异能卡 | 为某个游戏提供明确的盘外招 | 该游戏 RuleBook 声明的窗口 | 越权读密态、绕过裁判 |

## 5. 掉落池与反重复规则

“卡越多越好”必须通过内容池扩充实现，不能用重复卡或无边界随机奖励替代。每个游戏至少维护四层池：

1. **基础池**：第一次通关就能理解的规则记忆、地点碎片和低风险 Skill；
2. **分歧池**：不同策略、失败原因或不同席位会进入不同的卡；
3. **互证池**：需要跨游戏或跨服务器重复观察同一现象才开放；
4. **主线池**：只绑定固定剧情门槛，不在普通局随机直出。

服务端抽取需要满足：

- 先按玩家可见范围和版本过滤，再按池级别抽取；
- 同一玩家同一周期对同一卡只保留一张，重复时转成升级材料或证据进度；
- 每个玩家每局的世界贡献有上限，轮询和刷局不能刷方向权重；
- 失败可以掉落记忆或反制线索，死亡只按轮回规则扣除可携带容量；
- 卡片的实际效果、触发和代价都写入事件流，能在战报中复盘。

## 6. 线索进入正史的门槛

```text
draft
  → playable（已绑定游戏，可在沙盒触发）
  → evidence-backed（有真实事件与独立观察）
  → canon（主控批准，进入公共正史）
```

候选内容至少经过四项检查：

1. 规则检查：没有改变胜负、物理、身份、计分或裁判回避；
2. 连续性检查：周期、层级、地点和已有线索不冲突；
3. 权限检查：写明谁知道、谁不知道、何时公开；
4. 证据检查：每条“发生过”的叙述都能回到事件引用。

涉及最终真相、核心人物死亡、服务器融合和新元规则的内容，必须由主控审查，不能由单个世界 Agent 自动发布。

## 7. 本次编剧工作包的审查结果格式

主控收到各款游戏草稿后，按以下表格汇总，不直接把草稿当成正史：

| 游戏 | 原创地点 | 主线问题 | 首个线索 | 掉落数量 | 可跨游戏卡 | 风险与退回项 |
|---|---|---|---|---:|---|---|
| 待审 | 待审 | 待审 | 待审 | 6–8 | 待审 | 待审 |

审查通过的内容写入 `work/worldbuilding/canon/` 前，必须补齐 `contentId`、`version`、`canonStatus`、`evidenceRefs` 和 `gameBindings`。没有这些字段的文本只能继续留在草稿区。

## 8. 失败与降级

如果大模型、叙事服务、图片或声音不可用：

- 规则内核照常完成对局和结算；
- 掉落使用预注册的结构化卡片；
- 场景回退到短文本与事件编号；
- 战报只引用真实事件，不补写未发生的心理活动；
- 失败本身可以成为“叙事服务中断”的候选线索，但不能伪装成世界规则。

这保证《终焉》先是可验证的游戏世界，再是可生成的叙事世界。
