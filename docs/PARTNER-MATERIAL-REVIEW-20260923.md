## 结论

这份材料的新增核心是“果蝇大脑·逗蛐蛐”内容包，包括：

- `flyTease` 游戏规则、服务端执行器和单元测试；
- 52 张刺激牌的离线响应表与前端脉冲雨演出；
- `flybrain` Python 子网引擎、可选 Brian2 引擎和响应表生成脚本；
- 联机虫室页面、牌堆面板和对局揭晓组件；
- 对应的规则书、部署说明和研究记录。

当前《终焉》的主线范围已经冻结为五个游戏：猜平均数、少数派票决、狼人杀、超能力赛马、海盗分金。伙伴提交不能整包覆盖，也不能直接加入官方游戏注册表，否则会覆盖当前的 Agent Gateway、跨阶段房间状态、海盗分金和外部 Agent 重连改动。

本次先将它登记为**候选内容包**，不计入黑客松首发五个游戏。后续若要启用，必须按当前协议重新适配并单独验收。

## 可以吸收到主架构的内容

### 1. 模型型内容包的离线响应表模式

这是最值得保留的工程模式：

```text
离线模型 / 实验脚本
        ↓
固定版本的响应表、生成元数据、校验摘要
        ↓
游戏模板读取确定性结果
        ↓
规则内核验证动作并结算
        ↓
事件流、观战投影、回放和高光演出
```

它适合未来的赛马特效、特殊挑战局和其他需要模型表现的内容。模型只产生候选行为或表现数据，不直接修改金币、积分、座位和胜负；共享事实仍由《终焉》规则内核维护。

### 2. 可复现的模型产物元数据

响应表中已经记录了引擎、版本、随机种子、时长、试验次数、通道和行为分布。这套做法可以抽象成所有模型内容包的通用字段：

- `modelId`、`modelVersion`；
- `atlasVersion` 或内容产物版本；
- 生成引擎和运行参数；
- 输入空间与输出空间；
- 生成时间和校验摘要；
- 降级状态及其说明。

这些字段应进入规则书或对局事件的可追溯元数据，便于答辩、审计和回放。

### 3. 脉冲雨与逐步揭晓的观战表现

`SpikeRain`、行为标签、逐轮揭晓和“模型响应 → 规则得分”的视觉链条可以复用到赛马和裁判辩论：先展示输入，随后展示响应，再展示规则效果，最后落到积分和事件流。它们属于表现层能力，不能替代服务端结算。

### 4. 模型服务与游戏服务分离

伙伴材料把 Python 模型工具放在 `flybrain`，游戏运行期默认读取静态表。这符合《终焉》的部署原则：比赛现场不依赖 Python 推理服务，模型服务关闭时仍能完成规则对局；需要重新生成内容时，再单独运行离线工具链。

## 暂不直接合并的内容

| 内容 | 决定 | 原因 |
|---|---|---|
| `flyTease` 加入 `OFFICIAL_GAMES` | 暂不合并 | 当前首发范围已冻结为五个主游戏，且果蝇此前已从主线移出 |
| 伙伴版 `registry.ts`、`runtime.ts`、`gameSdk.ts` | 不直接合并 | 这些文件基于旧 SDK；当前主线已经增加 `pirateGold`、阶段状态、重连和世界协议，补丁无法干净应用 |
| `FlyOnline.tsx` 与旧大厅向导改动 | 暂不合并 | 路由、房间视图和创建定义需要先适配当前协议，不能只复制页面 |
| `flybrain` 目录作为线上依赖 | 暂不合并为运行时依赖 | 默认是子网响应表；Brian2 全脑运行成本高，不适合每次对局实时调用 |
| 伙伴 ZIP 中的 `.env` | 永不合并 | 环境文件不得进入仓库或内容包；认证信息只能由部署环境注入 |
| 伙伴版 `GAMES.md`、`ARCHITECTURE.md`、`DEPLOY.md` | 不覆盖当前文档 | 当前文档包含较新的五游戏范围、TDG-WP、Agent Gateway 和部署决策 |

## 如果后续重新启用果蝇内容包

它应放在独立的 `content-packs/fly-tease` 工作流中，接入顺序如下：

1. 把 `flyTease` 重新实现为当前 `GameDefinition` 和 `TemplateModule` 的适配器。
2. 根据当前 `GameAction`、`matchState`、事件流和三种投影接口重写房间接入。
3. 通过 Agent Gateway 暴露牌堆目录、观察接口和结构化出牌动作。
4. 把响应表的版本、引擎、生成参数和校验摘要写进游戏定义或对局元数据。
5. 补齐真人、外部 Agent、观战、断线重连、超时和回放验收。
6. 只有完成服务端结算、CLI 游玩和页面验收后，才可以加入官方游戏目录。

## 当前合并动作

- 不覆盖当前主线文件。

- 保留伙伴代码作为后续内容包适配输入；评审临时解压目录不作为项目依赖。
