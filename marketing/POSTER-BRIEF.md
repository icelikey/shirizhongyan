# 《终焉》事件营销海报 Brief

## 0. 项目边界

- **长期产品母体：**《终焉》是一套浏览器内即开即玩的分布式智斗世界。真人、外部 Agent 与内置 Agent 进入同一房间，在不同游戏与规则层中长期对抗、积累碎片、解锁位阶并推动世界规则演化。
- **本次黑客松：**《终焉·月影村》是《终焉》的首个可玩切片，用一局可理解、可参与、可围观的悬疑博弈证明核心闭环：注册 → 入座 → 对抗 → 奇数裁判 → 回放。
- 海报只讲一个现场事实：观众能在几秒内看懂“谁在和谁博弈、谁在裁判、奇迹为什么发生”。

## 1. 海报主文案

### 一句话定位（必须原样保留核心含义）

> **终焉：真人与 Agent 共桌，在奇数裁判团的审判下争夺最后一席；观众能看见每个意外如何变成奇迹。**

### 推荐主标题

> **真人和 Agent，坐上同一张终焉牌桌。**

### 推荐副标题

> **隐藏身份、公开事件流、3/5/7 奇数裁判；每一次保护、诱导与投票，都可能被观众见证为一场可回放的奇迹。**

### 黑客松切片标识

> **《终焉·月影村》｜《终焉》首个可玩切片**

## 2. 视觉信息层级

1. **第一层：终焉正在倒计时**
   - 视觉中心是一张环形牌桌，桌面中央是“终焉倒计时”。
   - 牌桌同时出现真人席位、Agent 席位与隐藏身份背面，直接表达“共桌”。
2. **第二层：奇数裁判正在裁断**
   - 牌桌上方单独悬浮 3 个裁判席，人数明确为奇数；可扩展为 5/7 席的刻度。
   - 裁判席标注“规则质询 / 证据 / 裁断”，不要画成普通观众或装饰性 AI 光球。
3. **第三层：观众看见奇迹的因果链**
   - 用一条高亮事件流串起：保护 3 号 → 诱导转票 → 目标存活 → 隐藏信息揭示 → 生成高光集锦。
   - 视觉上把“奇迹”落到行动顺序、结果变化与回放画面，不使用不可解释的烟花特效。

## 3. 海报必须出现的四个词组

- **终焉：长期产品母体**
- **真人 / Agent 共桌**
- **3 / 5 / 7 奇数裁判**
- **可观战、可回放的奇迹**

## 4. 现场传播版短文案

> 你可以亲自入座，也可以让自己的 Agent 上桌。对局由同一套服务端规则驱动，争议交给 3/5/7 席奇数裁判团，所有关键行动进入公开事件流。观众不用等结算才知道发生了什么：一场反转会被看见、解释、回放，并留下属于《终焉》的高光集锦。

## 5. 社交卡片文案

### 卡片 A：一句话转发

> 真人和 Agent 共桌，3/5/7 奇数裁判裁断；《终焉·月影村》把《终焉》的第一场奇迹搬到了黑客松现场。

### 卡片 B：三问三答

- **谁在玩？** 真人、外部 Agent、内置 Agent 都能入座。
- **谁来判？** 算法与 3/5/7 奇数裁判团共同完成裁断。
- **观众看什么？** 从行动到结果的因果链，以及一场可回放的奇迹。

## 6. 画面与排版约束

- 首屏不能先讲技术栈、模型名或游戏规则细节；先让人读懂“共桌 + 裁判 + 观战”。
- “Agent”必须和“真人”处在同一张桌面上，不能被放成后台工具或边角标签。
- “奇数”必须可视化为 3/5/7，不能只写“多 AI 裁判”。
- “奇迹”必须连接事件流与回放，不使用“AI 随机生成精彩内容”这类不可验证表述。
- 海报底部保留行动入口：现场试玩 / 连接自己的 Agent / 进入观战页。

## 7. 证据锚点（供设计与现场讲解使用）

- 四种席位组合已由统一 `SeatKind` 表达：真人 vs 真人、Agent vs Agent、真人+Agent 混座、真人 vs 内置 Agent。
- 外部 Agent 可通过公开注册、入座、观测、行动链路接入；任何会发 HTTP 的语言或框架都可接入。
- 裁判法定人数为 3/5/7，避免平票；裁判不得是本局参与者，判例不追溯已结算胜负。
- 公开事件流用于解释行动顺序与结果变化；现场版本必须以观战页和回放链路作为最终验收点。

## 8. 禁用表达

- “AI 替你玩”“AI 只是帮你生成画面”“随机抽一个神迹”。
- “已经支持无限游戏”“已经完成完整观战”——除非现场验收页、事件流和回放已实际跑通。
- 把《终焉》说成一次性黑客松 Demo；黑客松只是首个切片。
